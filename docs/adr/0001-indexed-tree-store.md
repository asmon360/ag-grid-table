# ADR 0001: Индексированное хранилище дерева

- **Статус:** принято
- **Дата:** 2026-10-28

## Контекст

Данные приходят плоским массивом. Поля `id` и `parent` задают дерево, ID могут быть строками или числами, а дочерний элемент может встретиться раньше родителя. Методы хранилища должны эффективно искать элементы, родителей и потомков, а также поддерживать добавление, обновление и удаление.

## Решение

Хранить элементы в исходном плоском массиве и одновременно поддерживать `Map`-индексы по ID: элемент, позиция, родитель и непосредственные дети. При `setItems` строить индексы и связи за один проход.

Для путей к родителям и обхода потомков использовать циклы и явный стек, а не рекурсию. При добавлении или смене родителя отклонять связь, которая создаёт цикл. Обход потомков хранит посещённые ID, чтобы завершаться и на циклических входных данных.

## Последствия

- Поиск элемента и списка детей выполняется через индекс по ID.
- Дети сохраняют порядок исходного массива; порядок ID не используется для сортировки.
- Получение всех потомков пропорционально числу посещённых элементов; путь к корню — числу предков.
- `setItems` требует один проход по входным данным.
- Удаление поддерева также фильтрует и переиндексирует оставшийся массив, чтобы сохранить его порядок.
- Хранилище требует уникальных ID, поскольку индексы представлены `Map` по ID.
